Idle Clicker RPG

Documentation Technique Synthétique

Projet Java - Développement de Jeu 2D

Durée : 3 semaines | Novembre 2025

1. Vue d'Ensemble du Projet

Idle Clicker RPG est un jeu 2D en Java combinant mécaniques clicker et RPG. Le joueur combat des monstres par clics, collecte de l'or, achète des améliorations aléatoires et recrute des familiers pour devenir plus puissant.

Concept Central

  • Die & retry : mourir pour progresser
  • 5 monstres → 1 boss (cycle répété)
  • Améliorations permanentes
  • Collection de familiers

Technologies

  • Java 11+ (JDK standard uniquement)
  • Swing pour l'interface
  • Serialization pour sauvegardes
  • Pas de dépendances externes

Gameplay Principal

Phase Description
Combat Cliquer sur monstres → infliger des dégâts → tuer → gagner gold
Boss Tous les 5 monstres : boss avec 3× HP, DPS continus, esquive (a équilibrer), bouclier (pareil)
Mort Retour monstre 1 de la phase, conservation gold/upgrades/familiers
Shop Acheter upgrades aléatoires (50g) ou œufs de familiers (200g)

2. Systèmes de Jeu

Système de Combat

Dégâts finaux = (Base + Upgrades + Familiers) × Crit Multiplier (si crit) Chance crit = 5% base + upgrades + familiers Boss esquive : 15-20% d'annuler l'attaque Boss bouclier : 5-8% d'activer 3 sec invulnérabilité
Stat Joueur Base Sources amélioration
HP Max 100 Upgrades shop (+10), Familiers
Dégâts/clic 10 Upgrades shop (+2), Familiers
Taux critique 5% Upgrades shop (+5%), Familiers
Mult. critique 150% Upgrades shop (+20%), Familiers

Système de Familiers

Créatures collectionnables qui boostent les stats. 2 slots équipables simultanément.

Rareté Prob. Bonus typique
Commun 50% +5 HP, +1 dégât, +2% crit
Rare 30% +15 HP, +3 dégâts, +5% crit
Épique 15% +30 HP, +6 dégâts, +10% crit
Légendaire 5% +50 HP, +10 dégâts, +15% crit, effets spéciaux

Shop et Progression

Améliorations (50g base)

  • Vie Max +10 HP (30%)
  • Dégâts +2 (30%)
  • Taux crit +5% (25%)
  • Dégâts crit +20% (15%)

Autoclicker

Débloqué après 5 boss vaincus (total)

  • Clique automatiquement
  • Toggle on/off
  • ~3 clics/seconde

3. Architecture et Diagramme UML

Architecture MVC-like avec séparation claire : Entities (Model), Systems (Controller), UI (View).

🎮 Couche Principale : Main, GamePanel (orchestration), GameState (enum), GameData (sauvegarde)
📦 Couche Entités : Player, Monster, Boss (extends Monster), Familiar, Rarity (enum)
⚙️ Couche Systèmes : CombatSystem, ShopSystem, UpgradeSystem, FamiliarSystem, BossAbilitySystem, AutoClickerSystem
🖥️ Couche UI : CombatPanel, ShopPanel, StatsPanel, FamiliarPanel

Classes Principales

Classe Responsabilités clés
GamePanel Game loop (60 FPS), coordination des systèmes, gestion des états, delta time
Player Stats (HP, dégâts, crit), gold, familiers équipés[2], collection complète
Boss HP ×3, DPS, esquive, bouclier (timer, cooldown, activation aléatoire)
CombatSystem processCombatClick() → calcul dégâts, gestion esquive/bouclier, retourne CombatResult
FamiliarSystem hatchEgg() → tirage pondéré de rareté, sélection familier aléatoire

Relations Importantes

  • Boss extends Monster : Héritage avec capacités supplémentaires
  • Player HAS-A Familiar[2] : Composition pour équipement (2 slots)
  • Player HAS-A List<Familiar> : Collection complète
  • GamePanel USES Systems : Composition, pas d'héritage
  • Systems sont stateless : Reçoivent entités en params, retournent résultats
Principe clé : Les systèmes ne stockent jamais d'état de jeu. Toutes les données sont dans les entités, ce qui facilite la sauvegarde (il suffit de sérialiser Player et GameData).

4. Spécifications Techniques

Classes sérialisables : Player, Familiar, GameData | Non sérialisées : Monster/Boss (recréés), Systems (sans état), Panels UI

Moments de sauvegarde : Après achat shop, équipement familier, mort joueur, victoire boss, fermeture jeu

5. Planning de Développement (3 Semaines)
